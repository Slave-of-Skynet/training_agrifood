## 4. Deployed runtime vs research benchmark boundary

**Category A — current deployed baseline.** The concrete serving artifact is `baseline-crop-median-v1-p1-s2024`, fitted on 900 Season-2024 training batches in the supplied snapshot. VDR-06A evaluates the application baseline under P1 forward inter-season holdout on 900 held-out Season-2025 batches from that snapshot; VDR-06B queried the **single-batch FastAPI path** for all 900 eligible held-out batches and verified the served scores and P1 metrics against VDR-06A. Exact current-engine metrics appear in §8. This proves bounded historical evaluation and runtime parity for the pinned snapshot. It does not prove external reliability, calibrated confidence, business effect, or that the 18-item replay queue has an independently measured ranking metric.

**Category B — research/benchmark, not deployed.** VDR-04A F0–F3 Ridge/HistGradientBoosting experiments, VDR-04B C/C+T/C+L/C+T+L ablations, and VDR-05 planned-logistics decompositions evaluate feature-family associations under P1/P2. Their fitted models are **not** the runtime engine. P2 crop-median OOF uses the same baseline algorithm but refits it for five grouped folds; those fold models are not the concrete P1-serving artifact. P3 random-split figures are non-defensible diagnostics because of chamber-cluster overlap. Research performance cannot be called “Smart Harvest's current model” performance. In particular, “Smart Harvest achieves F3 HGB results,” “our deployed model uses planned logistics,” and “our current model achieves the best VDR-04A ranking metrics” are false at this base. VDR-05's logistics signal is association, not proof that changing vehicle or route causes a loss change. Sources: ADR 0003/0004; `docs/evaluation.md`; VDR-04A/04B/05 and JSON artifacts; VDR-06A/06B and JSON artifacts.
